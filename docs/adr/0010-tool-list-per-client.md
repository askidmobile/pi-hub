# ADR-0010. Список инструментов зависит от клиента: динамический для Claude Code, статический для Codex

**Статус:** Предложено (2026-11-26). Закрывает OQ-07.

## Контекст

Спецификация: в выключенном режиме виден только `architect_mode`; `/architect on` отправляет `notifications/tools/list_changed` и открывает остальные инструменты.

Проверка (2026-11-26, тестовый MCP-сервер, инструмент `unlock` включает скрытый `secret` и шлёт `list_changed`; в журнале сервера уведомление отправлено):

- **Claude Code** — поддерживает `list_changed` по документации: список обновляется без переподключения.
- **Codex CLI 0.171.0** — не поддерживает: `secret` не появился ни в том же ходе (`codex exec`), ни в следующем ходе интерактивной сессии. Список инструментов фиксируется при старте сессии.

## Решение

Фасад выбирает поведение по типу клиента из `Hello.client` (с переопределением в конфиге хаба `clients.<kind>.tool_list = dynamic | static`):

- **dynamic** (Claude Code, по умолчанию для клиентов, про которых известно, что они поддерживают `list_changed`): как в спецификации — при `off` виден только `architect_mode`, при `on` — `list_changed` и все 8 инструментов.
- **static** (Codex, по умолчанию для неизвестных MCP-клиентов): все 8 инструментов видны с начала сессии; при `off` хаб отклоняет вызовы делегирования коротким ответом «режим архитектора выключен, включите `/architect on`». Запрет по-прежнему держит хаб, а не промпт.

Почему это приемлемо для Codex: инструменты pi-hub видны только в профиле `codex --profile pi-hub` (ADR-0009), то есть пользователь уже явно выбрал режим архитектора. Обычный `codex` pi-hub не видит — уровень 1 «цена ноль» сохраняется. Плата — описания 8 инструментов вместо одного в сессиях профиля; поэтому описания инструментов держим максимально короткими.

Для Codex по умолчанию режим в профиле можно включать сразу (`delegation_on_connect = true` в `clients.codex`), чтобы не требовать лишнего шага.

## Последствия

- В `Hello` уже есть `client`; фасад получает таблицу возможностей клиентов. Если Codex добавит поддержку `list_changed`, достаточно переключить `clients.codex.tool_list` на `dynamic`.
- Тест: интеграционный тест фасада на оба режима; `pi-hub doctor` показывает, какой режим выбран для клиента.
- Перепроверять при обновлениях Codex (тест с `unlock`/`secret` описан выше).

## Дополнение (этап 3, 2026-11-27)

Решение D-207 спецификации этапа 3 отменяет совет выше: у Codex, как у всех клиентов, режим при подключении выключен (`delegation_on_connect: false`). Инструменты видны (статический список), хаб отклоняет вызовы до `/architect on`.
