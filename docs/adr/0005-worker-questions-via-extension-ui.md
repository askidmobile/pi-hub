# ADR-0005. Вопросы воркера через Extension UI Pi

**Контекст.** Воркер должен задать вопрос и ждать ответа без трат токенов; хаб должен узнать о вопросе сразу.

**Решение.** Расширение pi-hub регистрирует инструмент `ask`, который вызывает `ctx.ui.select`/`ctx.ui.input`. В RPC-режиме это `extension_ui_request` в stdout Pi, расширение блокируется до `extension_ui_response` с тем же `id`. Хаб — это и есть «клиент UI». Отдельного канала расширение ↔ хаб нет.

**Последствия.** Нет второго сокета и аутентификации расширения. Таймаут диалога не задаём (ждём сколько нужно); если старший молчит — уведомление пользователю. Перехват опасных команд при желании делается тем же расширением на событии `tool_call` с `confirm`.

**Проверено (2026-11-26, Pi 1.6.1):** `ctx.ui.select` из расширения пришёл по RPC как `extension_ui_request` с `title` и `options`, ответ `extension_ui_response {id, value}` вернулся в расширение (ADR-0011).

## Дополнение (2026-11-27, этап 2)

Реализовано в этапе 2 ([спецификация](../specs/2026-11-27-stage-2-questions-quality.md), [план](../plans/2026-11-27-stage-2-questions-quality.md), решения PD-103, PD-104, PD-112).

- **Маркер диалога.** `ask` открывает только `ctx.ui.input`, а не `select`: ответ старшего передаётся как есть, варианты — подсказка (D-111). Заголовок диалога — `pi-hub:ask <json>` с вопросом и вариантами. Хаб отвечает только на такие диалоги; любой другой диалог расширения (`select`, `confirm`, `editor`, `input` без маркера) получает отказ `{cancelled: true}` и запись в журнал хаба. Вид вопроса определяет хаб по статусу задачи: `ask` в фазе `planning` — это план (`kind = plan`).
- **Живой процесс на `needs_input`.** Процесс Pi не останавливается, пока задача ждёт ответа: ответ на `ask` — `extension_ui_response` в тот же процесс. Таймер длительности (если задан) стоит на паузе; ожидающая задача не занимает слот воркера (PD-101). Останавливается Pi только после итогового статуса, `cancel` или остановки хаба. При остановке хаба задача становится `interrupted`, вопрос остаётся открытым, а `send` поднимает ту же сессию Pi и передаёт воркеру текстом «вопрос — ответ».
- **Вопрос текстом.** Дешёвая модель иногда спрашивает в итоговом сообщении вместо `ask`. Если итог без `SUMMARY:` заканчивается абзацем с «?», хаб оформляет его как вопрос `kind = text`; ответ уходит новым `prompt` в тот же процесс (FR-120, D-113). Отмены и перезапуска задачи за такое нарушение нет.
- **Консультанта нет.** Все вопросы идут старшему; System One и консультант — этап 4.
- **Проверено** на Pi 1.6.1 и `9router/Deepseek-v4.1-flash`: `ctx.ui.input` приходит как `extension_ui_request {method: "input", title}`, ответ возвращается в инструмент, после `agent_settled` тот же процесс принимает новый `prompt` (фикстура `packages/hub/test/fixtures/pi-session-ask.jsonl`, сквозная проверка `pnpm e2e --scenario ask`).
