# ADR-0008. Умный роутер: выбор при первом запуске, провайдер и модель System One

**Статус:** Предложено (2026-11-26). Закрывает OQ-04, OQ-09, OQ-10.

## Контекст

Спецификация предполагает System One модель для выбора роли и сложности задачи, оценки критичности вопроса, решения об эскалации, обнаружения зависшего воркера и оценки риска диффа. Пользователь должен сам решать, нужен ли ему умный роутер, и сам выбирать провайдера и модель. Хаб не должен зависеть от одного вендора.

Факты на 2026-11-26 (источники — [research/system-one.md](../research/system-one.md)):

- System One API — общий формат «решающих моделей»: `POST …/systemone`, тело `{model, state, questions}`. Типы вопросов: `choice`, `noul` (вероятность «да»), `score`; в ответе `answers` с вероятностями и `confidence`, плюс `usage`.
- Совместимые модели: TypeSafe Jev (создатели формата, прямой API `api.typesafe.ai`), Cloudflare Clef / Clef-flash (открытые веса, Apache 2.0), локальные модели через Ollama, Microsoft-Decision-1 (совместимость с форматом не подтверждена).
- Провайдеры расходятся в деталях: путь (`/v1/systemone`, `/v1/decisions`, `/ai/run`), где лежат `questions`, есть ли стоимость в `usage`.
- pi-jev ставить в воркеров не нужно: маршрутизацией и учётом владеет хаб. ACP-адаптеры для Pi не нужны: хаб работает с Pi через RPC напрямую.

## Решение

### 1. Выбор при первом запуске

`pi-hub init` (и потом `pi-hub router setup`) задаёт вопросы по шагам:

1. **Использовать умный роутер?** Да или нет. «Нет» — режим правил (ниже), остальные шаги пропускаются.
2. **Провайдер:** список готовых пресетов или «свой адрес».
3. **Адрес:** подставляется из пресета, можно изменить.
4. **API-ключ:** вводится скрыто и сохраняется в `~/.pi-hub/.env` (права 0600) под именем переменной из пресета. В `config.yaml` пишется только имя переменной, сам ключ — никогда.
5. **Модель принятия решений:** список моделей пресета или своё имя.
6. **Проверка:** один тестовый `noul`-вопрос; показываются задержка, ответ и стоимость, если провайдер её вернул. При ошибке можно исправить шаг или выбрать режим правил.

Неинтерактивный вариант для build-box: `pi-hub init --router=off` или `--router-preset=openrouter --router-model=typesafe/jev-latest --router-key-env=OPENROUTER_API_KEY`.

Посмотреть и изменить настройки потом: `pi-hub router status | setup | test | off`.

### 2. Пресеты

| Пресет | Адрес | Диалект | Ключ | Модели по умолчанию |
|---|---|---|---|---|
| **TypeSafe** (по умолчанию) | `https://api.typesafe.ai/v1/systemone` | `systemone` | `TYPESAFE_API_KEY` | `jev-latest` (→ 1.14.0), `jev-1.14.0`, `jev-1.13.0`, `jev-preview` |
| OpenRouter | `https://openrouter.ai/api/v1/systemone` | `systemone` | `OPENROUTER_API_KEY` | `typesafe/jev-latest`, `typesafe/jev-1.13` |
| AIML API | `https://api.aimlapi.com/v1/decisions` | `systemone` (другой путь) | `AIMLAPI_KEY` | `typesafe/jev`, `typesafe/jev-1.14` |
| Ollama (локально) | `http://localhost:11434/v1/systemone` | `systemone` | — | `nimble`, локальные Tev |
| Ollama Cloud | `https://ollama.com/v1/systemone` | `systemone` | `OLLAMA_API_KEY` | `clef:cloud` |
| Cloudflare Workers AI | `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/run/…` | `cloudflare-run` | `CLOUDFLARE_API_TOKEN` | `@cf/cloudflare/clef-flash`, `@cf/cloudflare/clef` |
| LiteLLM-прокси | `http://localhost:4000/v1/systemone` | `systemone` | `LITELLM_API_KEY` | задаёт пользователь |
| Свой адрес | любой System One-совместимый (например, `laya-serve`) | `systemone` | необязателен | задаёт пользователь |

TypeSafe — первый и предлагаемый по умолчанию пресет: это создатели Jev и формата System One. Ключ берётся в консоли `console.typesafe.ai/keys`. Список моделей можно обновлять запросом `GET https://api.typesafe.ai/v1/models`.

Адреса и модели — данные (`packages/hub/src/router/system-one/presets.ts`), а не код. Список обновляется без изменения адаптера. Microsoft Foundry добавляется, когда будет подтверждена совместимость формата.

### 3. Адаптер

Один внутренний интерфейс `SystemOneAdapter.decide(state, questions)` и маленькие «диалекты» для различий провайдеров:

- `systemone` — `POST {url}` с телом `{model, state, questions}`, `Authorization: Bearer`;
- `cloudflare-run` — тот же `{state, questions}` внутри входа `/ai/run/{model}`.

Ответ приводится к единому виду: для каждого вопроса — вероятности и `confidence`. `usage.cost`, если есть, пишется в `steps` с `cost_source = provider`; иначе — токены × цена из `prices` (у TypeSafe стоимости в ответе нет: $0.042 за 1M входных токенов, выходные бесплатны). Каждый запрос System One учитывается как шаг (роль `router`).

### 4. Что решает System One и что без неё

| Решение | С умным роутером | В режиме правил |
|---|---|---|
| Роль задачи без `role` от старшего | `choice` по ролям из таблицы; ниже `min_confidence` — `default_role` | `default_role` |
| Сложность → модель сильнее в роли | `score` | базовая модель роли |
| Нужна фаза вопросов | `noul` | только если старший указал `clarify` |
| Риск → ревью перед слиянием | `choice` low/medium/high | нет |
| Критичен ли вопрос воркера | `noul`: критичный — старшему, остальные — консультанту | все вопросы — старшему |
| Эскалация после FAIL | `noul` + правило «2 FAIL подряд» | только правило «2 FAIL подряд» |
| Воркер завис | `noul` по хвосту журнала | таймаут без событий |

Пороги уверенности задаются в конфиге и подбираются по накопленным данным.

### 5. Отказ System One

Если провайдер недоступен, превышен таймаут (по умолчанию 3 с) или ответ не прошёл проверку схемы, решение принимается по правилам, а в `tasks.routed_by` пишется `rules` и причина `system_one_unavailable`. Задача не блокируется. После N сбоев подряд хаб предупреждает пользователя и в `doctor`.

## Последствия

- Хаб работает без System One с первого дня; умный роутер включается и выключается без переустановки.
- Ключ System One хранится там же, где ключи провайдеров, и подчиняется тем же правилам.
- Внешний Jev Router (OQ-09) не нужен: выбор модели из своего списка — это `choice`-вопрос нашего адаптера по нашей таблице ролей.
- Нужно поддерживать список пресетов; первичная проверка — `pi-hub router test` и контрактные тесты диалектов на записанных ответах.
