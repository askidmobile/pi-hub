# ADR-0004. Pi как дочерний процесс в режиме RPC

**Контекст.** Нужны изоляция задач, отмена, смена модели, учёт токенов и восстановление после рестарта. Pi предлагает SDK (в процессе) и RPC (дочерний процесс).

**Решение.** Один `pi --mode rpc` на задачу, `cwd` = worktree, ключи только в env процесса, `--session-dir` в каталоге хаба, имя сессии = `task_id`. Адаптер `PiRpcClient` поверх экспортируемого `RpcClient` и типов `rpc-types.ts`; если `RpcClient` не даёт нужных опций запуска — своё JSONL-кадрирование (только LF, без `readline`). Версия Pi закреплена в конфиге хаба.

**Последствия.** Падение воркера не роняет хаб; при рестарте хаба процессы умирают — статус `interrupted` и продолжение через `switch_session`. Контрактные тесты на записанных JSONL-сессиях ловят изменения формата при обновлении Pi.
