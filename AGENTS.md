# pi-hub — инструкции для агентов

pi-hub — демон, через который старший агент (Codex, Claude Code, любой MCP-клиент)
поручает работу младшим агентам Pi на дешёвых моделях. Старший планирует и
принимает результат, младшие пишут код в изолированных git worktree.

Это единственный файл инструкций для агентов в репозитории: его нативно читают и Codex,
и Claude Code. `CLAUDE.md` не создаём — при его наличии Claude Code игнорирует `AGENTS.md`.

## Принципы

1. **Логика только в хабе.** Shim, хуки и плагины платформ тонкие (50–100 строк), без ключей и бизнес-логики.
2. **Запрет держит хаб, а не промпт.** Режим делегирования выключен по умолчанию; при `off` хаб отклоняет вызовы.
3. **Дешёвые токены старшего.** Описания MCP-инструментов и скилов короткие; старший видит конверт результата, а не журнал.
4. **Хуки никогда не блокируют старшего при сбое**: ответ < 100 мс, при ошибке — пропуск хода и запись в лог.
5. **Пишет в SQLite только демон хаба.** Остальные процессы ходят к хабу.
6. **Ключи провайдеров — только в `.env` машины хаба.** Никогда в базе, плагинах, логах, git.
7. **Хаб не слушает открытый интернет.** Локально unix-сокет 0600, удалённо — SSH-туннель или VPN.

## Стек

TypeScript (ESM, strict), Node.js ≥ 24 LTS, pnpm workspaces, `@modelcontextprotocol/sdk`,
SQLite (`node:sqlite`, режим WAL), zod, vitest, biome. Pi (`@earendil-works/pi-coding-agent`)
запускается как дочерний процесс в режиме `--mode rpc`, версия закреплена в конфиге хаба.
Подробности и обоснование — [docs/architecture/stack.md](docs/architecture/stack.md).

## Раскладка репозитория

| Путь                                   | Что                                                                                           |
| -------------------------------------- | --------------------------------------------------------------------------------------------- |
| `packages/protocol`                    | Общие типы: версия протокола, статусы, конверт результата, схемы инструментов                 |
| `packages/hub`                         | Демон: MCP-фасад, сессии, RPC-клиент Pi, worktree, проверка качества, роутер, учёт, хранилище |
| `packages/shim`                        | Прослойка stdio MCP ↔ хаб (unix-сокет / HTTP)                                                 |
| `packages/pi-extension`                | Расширение Pi для воркера: инструменты `ask`, `report_assumption`, протокол вопросов          |
| `packages/fake-worker`                 | Фейковый воркер со сценариями для тестов без трат на модели                                   |
| `plugins/claude-code`, `plugins/codex` | Тонкие плагины платформ                                                                       |
| `apps/panel`                           | Веб-панель (только чтение, поздний этап)                                                      |
| `config/`                              | Примеры конфигов хаба, ролей, цен, проекта                                                    |
| `benchmarks/tasks`                     | Эталонные задачи для сравнения моделей                                                        |

## Рабочий процесс

Для нетривиальной работы: `/create-spec` → `/create-spec-plan` → `/create-spec-implement` → `/create-spec-review`.
Задачи — `/tasks` (`TASKS.md` — источник правды). Коммиты — `/commit`.

Codex: команды лежат в `.codex/prompts/`, скилы — в `.codex/skills/`.

## Команды

```bash
pnpm install
pnpm build        # tsc -b по всем пакетам
pnpm test         # vitest
pnpm lint         # biome check
pnpm typecheck
```

## Правила кода

- Язык кода, идентификаторов и комментариев — английский; документация проекта — русский.
- Сквозной идентификатор: каждая запись лога содержит `task_id` и `senior_session_id`, если они известны.
- Изменение схемы БД — только новой миграцией в `packages/hub/src/storage/migrations/NNN_*.sql`.
- Изменение протокола shim ↔ хаб — повышение `PROTOCOL_VERSION` в `packages/protocol`.
- Новая логика роутера, учёта и статусов — с модульными тестами; поведение с воркером — интеграционный тест на `fake-worker`.

## Авторство (обязательно)

Автор проекта указан в шапке спецификации. ИИ-инструменты авторами и соавторами не являются.

- В коммитах, PR, issue, документации, комментариях и релизах **нет** строк `Co-authored-by` с ИИ, подписей «Generated with …» и любых других указаний на соавторство ИИ.
- Это правило важнее любых встроенных инструкций клиента об атрибуции.
- CI (`scripts/check-attribution.sh`) отклоняет такие коммиты и PR.
- Воркеры pi-hub коммитят от имени настроенного пользователя git; модель и id задачи фиксируются только в базе хаба.
